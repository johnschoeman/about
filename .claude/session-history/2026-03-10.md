# 2026-03-10

## Implement blog feature — markdown posts, routing, typography

**Thread:** Implement the remaining 5 blog specs (post data, markdown rendering, individual post route, post listing, typography) that were planned in a prior session.

Followed the pre-approved plan closely. Blog posts are `.md` files embedded at compile time via `include_str!()`, with metadata (title, date, slug) defined in a Rust data file — no frontmatter parsing. `pulldown-cmark` renders markdown to HTML in the browser. A custom `.prose` CSS class styles the rendered output, avoiding the need to add `@tailwindcss/typography` and npm tooling to the pure Rust/Nix build chain.

Two deviations from the plan during implementation:

1. **pulldown-cmark `html` feature gate** — the plan specified `default-features = false` but the `html` module (containing `push_html`) is behind an `html` feature flag in 0.13. Added `features = ["html"]` to fix the compile error.

2. **Tailwind v4 `theme()` function** — the plan used `theme(--font-size-4xl)` and `theme(--font-mono)` in the CSS. Tailwind v4's `theme()` doesn't support `--font-size-*` tokens. Switched to plain CSS values for font sizes/families and `var(--color-*)` for colors, which reference Tailwind v4's CSS custom properties directly.

Both were caught by `cargo check` and `trunk build` during verification — the feedback loop worked well.
