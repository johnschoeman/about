## Dependency update — Leptos, rand, getrandom

**Thread:** Update all Rust dependencies to latest versions and validate the build.

Followed a pre-planned update: Leptos 0.8.8→0.8.17, leptos_router 0.8.6→0.8.12, rand 0.9→0.10 (major), getrandom 0.3→0.4. The rand 0.10 migration required changing `use rand::Rng` to `use rand::RngExt` in both doodle files — the `random_range()` method moved traits. Also deleted `.cargo/config.toml` since the `getrandom_backend="wasm_js"` cfg flag is deprecated; the `wasm_js` feature in Cargo.toml is sufficient.

Build validation hit a NixOS environment issue: the rustup-managed nightly toolchain's binaries reference a glibc (2.40-66) that's been garbage-collected from the nix store, so `cargo` couldn't execute directly. Worked around this by using `nix-shell -p cargo rustc` to get working toolchain binaries. Validated `cargo check` (dev + release, wasm32 target) and `cargo clippy` — all pass with only pre-existing warnings.

`trunk build` compiled Rust/WASM successfully but failed on the Tailwind CSS step — nix provides Tailwind v3 (`tailwindcss_3-3.4.17`) but the project uses Tailwind v4 via trunk's built-in `tailwind-css` integration. This is a pre-existing local env issue unrelated to the dependency changes. Netlify uses `brew install tailwindcss` which provides v4.

## Add devenv for local development

**Thread:** Fix the broken local dev environment (rustup glibc rot + missing Tailwind v4) by adding a devenv configuration.

Picked up where the previous session left off — that session identified the two root problems (rustup nightly linking against GC'd glibc, nixpkgs only providing Tailwind v3) and suggested a nix shell/flake as a fix. Went with devenv since it was already installed on the machine alongside direnv.

Created `devenv.nix` with `languages.rust` (nightly channel via rust-overlay, wasm32 target), `pkgs.trunk`, and `pkgs.tailwindcss_4`. Added a `processes.serve` so `devenv up` runs `trunk serve`. The initial `devenv test` failed because `languages.rust.channel` requires the `rust-overlay` input — the plan hadn't accounted for this. Fixed by running `devenv inputs add rust-overlay github:oxalica/rust-overlay --follows nixpkgs`, which updated `devenv.yaml` automatically.

Also created `.envrc` for direnv auto-activation. The first attempt used a `source_url` pointing to a pinned GitHub commit of `direnv_support.sh` — this 404'd because that commit hash no longer exists upstream. Switched to the modern approach (`eval "$(devenv direnvrc)"`) which loads the integration from the local devenv install instead of fetching from GitHub. This is the recommended method for devenv v1.4+.

Verified: `devenv test` passes, `cargo check --target wasm32-unknown-unknown` compiles, `trunk build` succeeds (Rust + Tailwind CSS processed). All pre-existing warnings only. Netlify CI (`netlify.sh`) left unchanged — it uses brew and works fine.
